# Hermes Documentation Plan

> **Documentation Philosophy**: Following the [Diátaxis framework](https://diataxis.fr/) - separating tutorials (learning), how-to guides (tasks), reference (information), and explanation (understanding).

> **Tone**: User-facing, usage-focused documentation. Explain *how to use* features, not *how they work* internally. The only exception is Triggers (especially Terminal, AI Calls, Compound Actions) which can be more technical for power users.

> **Note**: This section is more technical than others. Triggers are a power-user feature for automation.

### 5.1 What Are Triggers? (`triggers/overview.mdx`)
**Purpose**: Introduction to the trigger system

**Content**:

#### The Concept
Triggers let you automate actions with your voice. When Hermes hears a specific phrase, it performs an action.

```
You say: "search google for best coffee shops nearby"
Trigger: "search google for"
Action: Opens Google search with "best coffee shops nearby"
```

#### Why Use Triggers?
- **Speed**: Actions happen instantly
- **Hands-free**: No clicking or typing
- **Consistency**: Same phrase, same result
- **Power**: Chain complex workflows together

#### Trigger Anatomy

```
┌─────────────────────────────────────────────┐
│                  TRIGGER                    │
├─────────────────────────────────────────────┤
│  Trigger Phrase: "window left"              │
│  Matching Mode:  Prefix                     │
│  Action Type:    Window Layout              │
│  Action Config:  Left Half                  │
│  Enabled:        Yes                        │
└─────────────────────────────────────────────┘
```

#### Trigger Types Overview

| Type | What It Does | Complexity |
|------|--------------|------------|
| Text Expansion | Replace phrase with text | Simple |
| Web Search | Search the web | Simple |
| App Launcher | Open applications | Simple |
| Window Layout | Snap windows to positions | Simple |
| Window Actions | Move/resize windows | Medium |
| Keyboard Shortcuts | Simulate key presses | Medium |
| Terminal Commands | Run shell commands | Advanced |
| Siri Shortcuts | Run Shortcuts app | Medium |
| AI Calls | Custom AI responses | Advanced |
| Text Formatting | Edit/reply to text | Medium |
| Compound Actions | Chain multiple actions | Advanced |

### 5.3 Matching Modes (`triggers/matching-modes.mdx`)
**Purpose**: Explain how trigger phrases are matched

**Content**:

#### Three Matching Modes

| Mode | Matches When | Example Phrase | Example Speech | Match? |
|------|--------------|----------------|----------------|--------|
| **Prefix** | Phrase is at the start | "search for" | "search for pizza" | ✅ |
| **Exact** | Phrase is the entire speech | "open mail" | "open mail" | ✅ |
| **Contains** | Phrase appears anywhere | "please" | "could you please help" | ✅ |

#### Prefix Match (Most Common)
Best for: Commands with variable input

```
Phrase: "search google for"
Speech: "search google for best coffee nearby"
                          └─── remainder ───┘
```

The remainder ("best coffee nearby") becomes available as `{remainder}` in your action.

#### Exact Match
Best for: Single-action commands

```
Phrase: "open slack"
Speech: "open slack"  ✅
Speech: "open slack please"  ❌ (doesn't match)
```

#### Contains Match
Best for: Catching phrases anywhere

```
Phrase: "reminder"
Speech: "set a reminder for tomorrow"  ✅
Speech: "don't forget the reminder"  ✅
```

#### How Matching Works (Technical)

Hermes uses a progressive matching strategy:

1. **Exact**: Normalized text equals normalized trigger
2. **Smart**: Handles plurals ("windows" → "window")
3. **Fuzzy**: Allows small typos (Levenshtein distance ≤ 2)
4. **Phonetic**: Matches homophones ("write" ≈ "right")

**Normalization**:
- Converts to lowercase
- Removes punctuation
- Collapses spaces
- Replaces hyphens with spaces

### 5.5 Web Search (`triggers/types/web-search.mdx`)

Opens a search engine with your query.

#### Configuration

| Setting | Default | Options |
|---------|---------|---------|
| Search Engine | Google | Google, DuckDuckGo, Bing, Custom |
| Browser | Default | Default, Safari, Chrome, Firefox |
| Query Handling | Passthrough | Passthrough, Template |
| Open in New Tab | On | On/Off |
| Focus Browser | On | On/Off |

#### Search Engines

| Engine | URL Pattern |
|--------|-------------|
| Google | `google.com/search?q={query}` |
| DuckDuckGo | `duckduckgo.com/?q={query}` |
| Bing | `bing.com/search?q={query}` |
| Custom | Your URL with `{query}` placeholder |

#### Custom Search Examples

| Site | URL Template |
|------|--------------|
| YouTube | `youtube.com/results?search_query={query}` |
| Amazon | `amazon.com/s?k={query}` |
| Stack Overflow | `stackoverflow.com/search?q={query}` |
| Wikipedia | `en.wikipedia.org/wiki/Special:Search?search={query}` |

#### Query Handling Modes

**Passthrough**: Uses your speech as-is
```
Speech: "search youtube for coding tutorials"
Query: "coding tutorials"
```

**Template**: Apply pretext/posttext
```
Pretext: "site:reddit.com "
Speech: "search reddit for best keyboards"
Query: "site:reddit.com best keyboards"
```

#### Variables
- `{query}` - The search query
- `{transcription}` - Full dictation

#### How App Matching Works

Hermes finds your app using:

#### Common Corrections

- "eye term" → iTerm

```
│ Bottom  │ Bottom  │  └───────────────────┘
│ Left    │ Right   │
└─────────┴─────────┘

┌─────────┬─────────┐  ┌───────────────────┐

│         │         │  │                   │

```

#### Multi-Monitor Support
Window layouts detect which screen your window is on and snap to that screen.

### 5.10 Terminal Commands (`triggers/types/terminal.mdx`)
**Purpose**: Run shell commands by voice

**Content**:

#### What It Does
Executes terminal commands, either silently or visually.

#### Configuration

| Setting | Default | Options |
|---------|---------|---------|
| Commands | Required | List of shell commands |
| Execution Mode | Background | Background (silent), Visual (shows terminal) |
| Terminal App | System Default | Terminal, iTerm, Warp, etc. |
| Working Directory | None | Directory to run in |
| Close Tab When Complete | Off | Auto-close terminal tab |
| Close Tab Delay | 2000ms | Wait before closing |

#### Execution Modes

**Background**: Silent execution
- No terminal window opens
- Output available via variable
- Best for quick commands

**Visual**: Shows in terminal
- Opens terminal app
- You see the command run
- Best for interactive commands

#### Command Structure

Each command has:
- `command`: The shell command
- `delayAfterMs`: Wait after running (default: 0)

#### Environment Variables

Your commands have access to:
- `$HERMES_INPUT` - Your transcription
- `$HERMES_SCREENSHOT` - Path to screenshot (if captured)

#### Screenshot Options

| Option | Resolution | Format | Use Case |
|--------|------------|--------|----------|
| None | - | - | No screenshot |
| Low Quality | 1280×720 | JPEG | Vision AI |
| High Quality | Full | PNG | Analysis |

#### Examples

**Open project in VS Code**:
```bash
cd ~/projects/myapp && code .
```

**Git status**:
```bash
git status
```

**Create and open file**:
```bash
touch ~/Desktop/notes.txt && open ~/Desktop/notes.txt
```

**Run with input**:
```bash
echo "$HERMES_INPUT" | pbcopy
```

#### Security Warnings

Hermes warns about potentially dangerous commands:
- `rm -rf` - Recursive delete
- `sudo` - Elevated privileges
- `curl | sh` - Remote script execution
- `shutdown`, `reboot` - System commands

> **Caution**: Terminal commands run with your user permissions. Be careful with destructive commands.

### 5.14 Compound Actions (`triggers/types/compound-actions.mdx`)
**Purpose**: Chain multiple actions together

**Content**:

#### What It Does
Runs multiple actions from a single trigger phrase.

#### Execution Modes

| Mode | Behavior |
|------|----------|
| Sequential | Run actions one after another |
| Parallel | Run all actions at the same time |

#### Error Handling

| Strategy | Behavior |
|----------|----------|
| Stop on Failure | Halt if any action fails |
| Continue on Error | Keep going despite failures |

#### Configuration

| Setting | Description |
|---------|-------------|
| Actions | List of actions to perform |
| Execution Mode | Sequential or Parallel |
| Error Handling | Stop or Continue on error |
| Pipeline | Pass data between actions |

#### Pipeline (Data Passing)

When enabled, output from one action can feed into the next:

```
Action 1: Web Search (returns URL)
    ↓
Action 2: AI Call (analyzes page)
    ↓
Action 3: Text Expansion (inserts result)
```

#### Example: "Research and Summarize"

```
Trigger: "research and summarize"
Actions:
  1. Web Search (Google) → Gets search results
  2. AI Call → "Summarize the key points"
  3. Inject → Insert summary at cursor
```

#### Example: "Setup Workspace"

```
Trigger: "setup dev workspace"
Actions (Parallel):
  1. App Launcher → Open VS Code
  2. App Launcher → Open Terminal
  3. Window Layout → VS Code to Left Half
  4. Window Layout → Terminal to Right Half
```

### 5.15 Variables & Templates (`triggers/variables.mdx`)
**Purpose**: Reference for all available variables

**Content**:

#### Global Variables

Available in all action types:

| Variable | Description | Example |
|----------|-------------|---------|
| `{transcription}` | Full dictated text | "send an email to John" |
| `{remainder}` | Text after prefix trigger | "to John" |
| `{selected_text}` | Currently highlighted text | "Hello world" |
| `{date}` | Current date | "January 15, 2025" |
| `{time}` | Current time | "3:45 PM" |
| `{app_name}` | Frontmost app name | "Safari" |
| `{bundle_id}` | App bundle identifier | "com.apple.Safari" |

#### Web Search Variables

| Variable | Description |
|----------|-------------|
| `{query}` | The search query |
| `{pretext}` | Text prepended to query |
| `{posttext}` | Text appended to query |

#### Template Syntax

Variables use curly braces: `{variable_name}`

**Simple substitution**:
```
Hello {transcription}
→ Hello how are you today
```

**Multiple variables**:
```
At {time} on {date}, you said: {transcription}
→ At 3:45 PM on January 15, 2025, you said: schedule meeting
```
